# Production configuration checklist (MVP-001)

Every environment variable name the application reads, what it is, where it is read, what refuses or fails closed
when it is missing or invalid, and the production-specific notes; then the configuration that lives in the database
or at the providers. **Names only: no value appears in this file.** The checklist excludes every development value:
the development-only items are listed in section 4 so that none of them reaches a production configuration.

This is preparation, not authorization: configuring production, making a jurisdiction live and activating production
payments are outside the Program (Packet §4).

declarations of each adapter. Re-checked at `2a1b94f`: the PS-A6 revision adds no `process.env` read under

relative to `apps/web/`.

## 1. Kinds and the common rule

- **S**: confidential value (held in the platform's secret store; never in the repository, a log or evidence).
- **C**: non-confidential configuration, server only.
- **P**: public by its `NEXT_PUBLIC_` prefix (inlined into the build).

Every provider setting is read through `src/infrastructure/environment/provider-configuration.ts:51–110`: a missing
setting or a missing or unknown `ROSUNO_ENVIRONMENT_CLASS` answers **unconfigured**; a value with surrounding
whitespace, a recognisable placeholder, the wrong shape, or the wrong shape for the current class answers
**refused**. Nothing is defaulted, inferred or replaced by a mock. An adapter that is not configured reports itself
unavailable, and a refusal names settings, never values.

## 4. Development values that must never reach production

- `ROSUNO_ENVIRONMENT_CLASS` set to `development` together with a loopback project URL and the local stack's keys
  (the local binding, `registration-provisioning.ts:275–330`). Outside development only a hosted project bound to
  `ROSUNO_SUPABASE_EXPECTED_PROJECT_REF` is accepted.
- Test-mode payment keys and webhook values: accepted in development and staging only; refused in production (D1).
- An `http` public origin: refused for the payment and email settings outside development (D9); still accepted by the
  two route readers, so it must not be configured.
- Development-only policy versions (`policy_versions.development_only`): creatable only in a development or staging
  database, never approvable and never selectable in production (PS-A2; S1 PS-A2-N1–N10).
- Synthetic rows of the proofs and L5 journeys: they exist only in disposable databases (Packet rule 10).

## 5. Build-time settings

`NEXT_PUBLIC_SUPABASE_URL` and `ROSUNO_DAILY_DOMAIN` are consumed when the build configuration loads (CSP
`media-src` and `frame-src`), and every `NEXT_PUBLIC_` value is inlined into the build. They must be present, with
production values, where the production build runs. Whether the hosting platform fixes the header table at build time
is not verified (ARCH-F17; L6, HOLD); a build is promoted only to the environment it was built for
(`release-traceability-procedure.md`, section 4).
