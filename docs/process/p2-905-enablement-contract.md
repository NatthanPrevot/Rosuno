## Trust model and gates

1. Existing `rosuno-guard` for Builder-fork PRs retains Packet-first, owner-mirror, per-commit scope/mode and historical-migration protections. It runs **only from trusted owner default-branch code** in `pull_request_target`; PR code is fetched as data only. `owner` PRs are **never silently accepted as PROCESS or closure success**.
2. The new `.github/workflows/rosuno-process-guard.yml` is intentionally **non-runnable** (`workflow_dispatch` job gated false), not in a required-check ruleset and not an operational source of successful commit statuses. The technical `.github/scripts/rosuno-process-guard.py` is a read-only validation engine, not an approval engine. Check-source registration, workflow enablement, policy enforcement, and required status are later gates.
3. The owner-origin PROCESS classification in the established required workflow is fail-closed unless separately commissioned with explicit trusted owner consent. It must verify actual owner repository numeric identity, PR author and event sender, owner-origin branch, exactly one open PR for the SHA, immutable Packet metadata and per-commit checks. The grant must be **fetched directly by a trusted workflow** from GitHub-authenticated API records. Never use PR-controlled JSON/metadata or a free-form token as proof of authorship.
4. The proposed future owner grant is one unedited authenticated PR comment by the owner, with exact marker `ROSUNO_PROCESS_GRANT_V1 ` followed by a JSON object with keys `version`, `repo_id`, `pr`, `head`, `base`, `branch`, `work_item`, `kind`, `expires_at`; exact source identifiers and a maximum 24-hour UTC validity. Source account ID, comment ID, author association and creation time must be verified from trusted GitHub API. This **defines a testable schema, not an issued grant**. A separately adopted enablement action must validate the procedure and operator permissions on disposable infrastructure before any live reliance. A non-PR-process closure contract is unresolved; all closure automation HOLD by default.
5. The read-only `rosuno-owner-executor-preflight.py` has **no mutation entrypoint**. Its baseline and identity checks do not empower an owner-executor principal or authorize another GitHub App. App/bot-authored owner PRs remain denied. Existing human-only owner PR + independent `Rosuno` reviewer + protected merge workflow remains controlling.
6. `CLOSURE_CANDIDATE` in `CLAUDE.md` is a disabled conditional role; Claude cannot edit its denied files, borrow a write connector, reach the owner repo or act as reviewer. Source-bound GitHub check evidence, exact closure Packet, human approval and isolated proof are prerequisites to any later commissioning.

## Source-bound readiness and negative cases

A future live trial must prove an actual owner-origin PROCESS PR receives a technical PASS **from trusted default-branch code**, without waiting on its own required check or a concurrent CI/Backup audit. Independently verify exact head/base, one open PR per head, authenticated grant, owner account/repository IDs, correct Packet body, per-commit file scope and mode, historical migrations, no case-collision/symlink and a valid unexpired single grant. Negative trials must refuse wrong or bot sender, App actor, spoofed PR/comment, edited grant, duplicate/expired grant, stale SHA/base, altered Packet, invalid branch, extra path, failed/absent status, false Backup receipt, and a prior security assertion removed/reverted within history.

After CI completes, independent Backup reviews **that exact head** plus each required live, source-bound status and its source. A changed head invalidates readiness; a simulated fixture PASS never qualifies. Approval of the protected PR and owner merge remain separate. Old `rosuno-guard` must remain required; introducing `rosuno-process-guard` as a second required context needs a separately authorized GitHub rule/source check and proof it actually reports on relevant PRs. No new status is treated as required during P2-905 Gate 2A.
